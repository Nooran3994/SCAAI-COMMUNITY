# Contributing to SCAAI Community

Thank you for wanting to help shape SCAAI! This repository is the public home for **releases**, **reviews**, **bug reports**, **feature ideas**, and **documentation** for SCAAI Desktop.

## Ways to contribute

### 1. Report a bug

Found something broken? Open a [bug report](https://github.com/Nooran3994/SCAAI-COMMUNITY/issues/new?template=bug_report.md).

Before opening:
- Search existing issues to avoid duplicates.
- Include your **SCAAI version** (Help → About) and OS (Windows 10/11 or macOS version).
- Attach logs if possible. SCAAI stores logs locally — include the relevant excerpt.
- **Security vulnerabilities must NOT be filed here** — use [SECURITY.md](SECURITY.md) and email `agents@systemprompts.site`.

### 2. Share a review

Used SCAAI and have thoughts? Open a [review](https://github.com/Nooran3994/SCAAI-COMMUNITY/issues/new?template=review_share.md). Reviews help us understand what works, what is confusing, and what is missing.

### 3. Suggest a feature / next-version idea

Ideas for the next version? Open a [feature request](https://github.com/Nooran3994/SCAAI-COMMUNITY/issues/new?template=feature_request.md). Each idea is tracked on the [ROADMAP](ROADMAP.md). The more specific the better: describe the problem, the use case, and a rough idea of the solution.

### 4. Improve documentation (including this README)

Docs are a community asset. To propose changes:

1. Fork the repository.
2. Make your changes on a new branch (`docs/fix-typo`, `docs/improve-readme`, ...).
3. Open a pull request against `master`.
4. A maintainer reviews and merges.

### 5. Contribute code (future)

SCAAI source is **not** published in this repository. This repo hosts release artifacts and community coordination. If/when source contribution opens, it will be announced here and on the [site](https://systemprompts.site).

## Pull request workflow

1. Fork the repo and create a branch: `git checkout -b your-branch-name`
2. Make focused changes — one logical change per PR.
3. Commit with a clear message (e.g. `docs: clarify update flow`).
4. Push and open the PR. Fill in the [PR template](.github/PULL_REQUEST_TEMPLATE.md).
5. Respond to review feedback. PRs are merged only after maintainer approval.

## Branch protection

- `master` is protected. **No direct pushes.**
- All changes land via pull request with at least **one maintainer review**.
- Only users with the **Contributor** role can be added to the repository; everyone else is read-only.

## Code of conduct

All contributions are governed by our [Code of Conduct](CODE_OF_CONDUCT.md). Be respectful, be constructive, assume good faith.

## Questions

Open a discussion or reach out at `agents@systemprompts.site`.
